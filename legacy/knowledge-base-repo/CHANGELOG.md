# Changelog

本文件记录 Obsidian Knowledge Base 公开仓库自建立以来的主要变化。

项目尚未发布语义化版本或 Git tag，因此以下内容按 Git 提交日期组织；提交短哈希用于追溯具体改动。仅记录公开代码、工作流与文档，不包含个人知识库内容、文献、配置、日志或本机路径。

## 2026-10-15

- 逐段精读命令和 `paragraph_reading` 勾选支持 Zotero 分类子目录中的主论文笔记，与 runner 的主笔记判定一致。
- 审核内容摘要排除“写入笔记”追加的 `# 提问` 对话；审核后写入对话不再使审核失效，正文其他修改仍会。插件、`run_pipeline.py` 与 `wiki_knowledge.py` 使用同一算法，并继续接受旧算法生成的摘要。
- 人工复核结果只认回答最后一行的 `REVIEW_STATUS` 隐藏标记，回答中复述的指令或引用的原文不能判定通过。
- 未配置 `codex_path` 时自动查找本机已安装的 Codex CLI，不再使用已失效的应用内路径。

## 2026-10-12

- 独立适配固定 LLM Wiki 源码中的题名/短语匹配、一跳查询种子扩展和 Adamic–Adar 邻居降权；保留显式别名及有效审核筛选，不引入向量检索或 RRF。
- 规范候选增加零模型的元数据归并、原身份/问题状态恢复和精确证据重复删除；保留一次完整模型候选与原声明条件，校验失败不覆盖现有页。
- 增加固定 top 4 的受控检索对照脚本，保留预设相关性案例的全部结果、无改善/退步和负例失败；实际私库案例及结果不进入公开仓库。
- 新增跨论文证据对比、同义概念建议和研究问题维护的真实 Obsidian 报告入口；比较使用问题弹窗，报告操作在生成暂停时可用，不调用模型或自动改写规范页。
- 显式同义映射由用户维护；多源比较保留各源声明、条件、页码与有效审核状态，审核后整合核对各自来源并保留问题的人工状态。
- 新增本地 `knowledge-context` 检索和 `knowledge-map --report` 关联整理线索，问答可显式加入带来源、页码及审核状态的相关片段；人工复核隔离其他论文。
- 增加用户维护的空白研究目标模板，仅供普通问答和审核后整合聚焦，不改变论文生成；记录对 LLM Wiki 的独立设计借鉴。
- 审核后整合改为模型仅编辑候选工作区内七类规范页，runner 校验证据与并发编辑后发布，并确定性更新源生命周期和索引。
- 准确报告 CLI 的终止错误和模型容量不足；支持用户明确指定单篇总时限，并同步延长 Obsidian 调用等待时间。
- 保留部分草稿的实际停止原因，避免将目录或时间戳数字识别为 HTTP 错误；重连检测兼容省略号格式。
- 完整正文先进入待校验状态，再处理可选配图；停滞检测同时计入已选图片的实际更新。
- 显式指定流水线图片目标时不再检查全局配置，正确解析分类笔记及其专属图片目录。
- 允许仅为 Forge 调用指定模型和推理强度，未设置推理强度时继续继承用户配置。

- Forge 规划阶段先保存 `planning` 检查点并逐项原子更新，全文阅读和必需字段完成后才标记 `ready_for_drafting`；部分计划可续跑但不能直接进入正文生成。
- 生成指引改为每次调用只读一次规则，禁止在文本输出中打印图片二进制/Base64；视觉核对限定具体证据疑点，可选配图留到完整正文保存之后。

## 2026-10-04

- 支持以 `forge_token_budget: null` 取消论文及各阶段 token 限制，显式关闭论文子任务的 CLI rollout budget；用量记录、墙钟期限、产物停滞保护和人工审核边界保留。
- 支持按任务 ID 显式重试，以及根据本地 PDF 封面补齐尚未生成笔记的论文元数据。

## 2026-09-23

### Zotero 子分类目录

- 递归同步 Doc 子分类，将 PDF 和论文主笔记按分类路径存放；同步索引保留分类信息和子分类参考文献。
- 迁移已有笔记与来源引用，保留人工内容、原有图片目录、任务状态和候选检查点；相同 DOI/文件内容的重新导入条目复用已有任务。
- 插件、精读、去重恢复和图片保存支持分类目录；增加 `--organize-only` 暂存新论文，以及单篇 `queue-held` 显式入队命令。

### Zotero 同步频率

- 新增文献自动检查从每分钟改为每3小时；保留启动同步、手动同步、本地队列每分钟处理和每小时 SI/JIF 补全。

### 生成止损与重复任务修复

- 在模型调用前恢复同版本已有笔记的队列状态；将完成凭据保存在本机缓存，拦截 iCloud 回退后的重复生成及已消费的重生成请求。
- 将单篇30分钟改为墙钟期限，增加10分钟无正文/计划更新停止机制；仅论文任务关闭 CLI 无限重连、自动目标继续和子代理。
- 增加阶段 token 预算分配、CLI 预算提醒及用量记录；自动模型修复默认关闭，显式修复保持有界。
- 正文逐节保存并区分未完成/待校验状态；失败候选稿不作为完整笔记发布，显式续跑复用已有计划、正文及图片，同时保留人工编辑冲突检测。
- 技术量校验不再强求论文同时具有实测及拟合/派生类别，避免综述和理论论文被误判或被迫补造条目。
- 增加离线回归测试，覆盖队列回退、旧请求、失败任务、预算、重连、休眠、断点恢复和部分草稿保护。

## 2026-09-16

### Doc Sync 调度修复

- PDF 同步与知识生成改用独立的每分钟定时器和忙碌状态，长时间 Forge/逐段精读任务不再阻塞文献刷新；同类任务仍禁止重叠。
- 知识处理器空闲时重新扫描来源，补录生成期间同步到的文献，并保留原有队列锁与人工审核门槛。
- 分开展示同步结果与生成进度，保留同步失败原因，避免被生成完成状态掩盖；增加并发调度与失败恢复回归测试。

## 2026-09-05

### 流水线可靠性与审核

- 修复插件 20 分钟超时早于 runner 30 分钟预算的问题；PDF 提取、计划、草稿和校验共享总期限，超时终止子进程组并保留输出。
- 保留 Forge 虚拟环境解释器的调用路径，避免解析符号链接后丢失 PDF 依赖；安装检查同时验证 PyMuPDF 与 Pillow。
- 将计划与撰写拆为独立调用，增加断点复用及仅校验/修复当前草稿的入口；额度、认证、网络、超时与编辑冲突分别记录。
- 使用候选工作区与原笔记快照，发布前检测并发编辑；保留问答、人工复核、用户块和已合并精读内容，更新配图另存版本。
- 队列扫描与重试统一加锁，锁文件放在本机缓存；中断运行状态可恢复。备份恢复后从已有主笔记重建任务状态。
- 后台 UI 显示阶段、已用时间和距输出的时间；未知比例使用不定进度条，不再把阶段编号显示为完成百分比。
- 对话审核同时写入生命周期状态和内容指纹；正文变化使旧审核失效，整合命令不再绕过审核。剩余警告由用户明确接受。
- 修正 follow-up 新颖性与否定语境术语的已知误报；文风/关键词警告不单独触发模型修复。
- 增加稳定论文身份与来源声明 ID，将精读日志和重复 PDF 视为同一来源的辅助或版本，不计为独立证据。
- PDF 同步与 SI/JIF 补全使用独立任务、缓存和锁。SI 网络错误与未发现分开记录，JIF 新验证值必须有年份、匹配期刊及直接官方证据。
- 新增通用私密备份脚本：候选快照校验、文件完整性清单、占位文件/大量删除拦截、无变化时仍重试推送，以及远端 HEAD 核验。

## 2026-09-03

### 新增

- 逐段精读增加直接 PDF 裁图脚本：每个 `Uxx` 单元的连续原文与相关图、表、公式统一存入论文专属 `images/.../intensive-reading/Uxx/`。
- Obsidian 增加显式“提交 Uxx 初始理解”按钮与命令；空内容由 runner 拒绝，单纯编辑不再触发状态推进。
- 逐段精读启动、提交、提示、解释和合并增加阶段化进度条与百分比反馈。
- 将 `forge-paper-note`、上游 `paper-reading` 和新建的 `paper-intensive-reading` 一并纳入公开仓库，提供统一安装与本地完整性检查脚本；补充第三方来源、固定上游版本和许可证说明。（`cd21f69`）
- 建立受控的交互式全文精读流程：连续覆盖全文、按推理单元推进、保留人工原文、分阶段提示与解释、0–8 分验证，以及达到门槛后的显式合并。（`a6af212`）
- 为逐段精读增加独立的 `paragraph-reading-merge` 工作流和检查脚本；精读日志复用主论文的图片目录，但不会自动进入规范知识层。（`a6af212`）
- 为 Forge 生成增加持久化 `note-plan.json`、运行检查点、表格规范化报告和三类确定性校验报告。（`952c916`）
- 增加 Markdown 表格规范化器及回归测试，自动转义表格内 Obsidian 链接、压缩页码别名并移除全空列。（`952c916`）
- 增加 Forge 计划、技术单位、列表断行、引用语言和材料论文流程的契约回归测试。（`74f74e7`）

### 变更

- 精读段落对移除重复显示的“原文”“翻译”标题，只保留 `Pxx` 与连续的原文、译文和段落相关配图。
- 精读原文由大片 PDF 文本裁图改为可搜索的提取文本，并按 `Pxx` 以“一段原文 → 紧跟该段翻译”交替呈现；相关图、表、公式仍直接从 PDF 裁切并插在对应段落之后。
- 精读单元仍按通常 4–8 个连续全文区段覆盖正文，只显示中性 `Uxx`、段落对、一次原文位置和交互；继续禁止 AI 推断的单元标题、作用和关系字段。
- 勾选当前论文的 `paragraph_reading` 后由插件自动启动精读；MinerU 提供可搜索原文、结构与页码导航，展示图像始终直接取自原 PDF。
- 已停在初始理解阶段的旧日志先显示“更新 Uxx 精读格式”按钮，只迁移展示契约而不推进阶段或改写人工内容。
- 将精读笔记明确设为主论文笔记的“验证与增量层”：主论文笔记是唯一可进入知识整合的论文来源，精读日志标记为辅助证据。（`03d0fee`, `a6af212`）
- Forge 单篇处理改为 30 分钟总预算内的两阶段生成：先完成全文分析并保存计划，再落盘完整草稿；runner 预留最后时间执行确定性校验和最多一次限时修复。（`952c916`）
- 前人工作、创新背景和 follow-up 校准限定为仅使用当前论文正文及其印刷参考文献，不联网检索或打开被引论文。（`952c916`）
- 前人工作表改用紧凑可点击引用，完整参考文献移至表外，减少重复说明和横向滚动。（`952c916`）

### 修复

- 阻止 `wiki/papers/close-reading/` 下的辅助精读日志被直接审核或整合，避免同一论文形成重复知识来源。（`03d0fee`）
- 修复 Forge pipeline 错用旧版计划字段契约的问题，并保持普通 DeepPaperNote 计划兼容。（`74f74e7`）
- 修复 Unicode 上标单位与 ASCII 单位写法无法匹配、编号列表被误判为断行、引用区英文题名被误判为中英混排的问题。（`74f74e7`）
- 材料、化学、制备和湿实验论文现在可以使用“材料制备步骤”作为领域原生方法流程，不再被强制要求重复的通用“机制流程”小节。（`74f74e7`）
